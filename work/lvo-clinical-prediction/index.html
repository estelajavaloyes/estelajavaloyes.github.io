01 / CLINICAL MACHINE LEARNING

The clinical question

Can information collected during the initial clinical assessment help identify patients with large vessel occlusion before imaging is available?

The project connects a clearly defined prediction question with clinical data preparation, model comparison and interpretation. Its value lies in evaluating what the data can support—and where the evidence stops.

02 / CLINICAL MACHINE LEARNING

Data & study context

The project summary describes a cohort of 251 acute ischemic stroke patients from Hospital Serena del Mar, using clinical variables available before neuroimaging.

The final research report is needed to document the precise eligibility criteria, outcome definition, missing-data patterns, event prevalence and partitioning of the cohort.

Evidence status. This case study is based on the supplied project summary. Cohort details and performance figures remain to be checked against the original thesis. No patient-level records are published here.

03 / CLINICAL MACHINE LEARNING

Modelling approach

The reported workflow spans data preprocessing, statistical analysis, class imbalance, three predictive-modelling families, hyperparameter optimisation, bootstrap confidence intervals, subgroup analysis and SHAP-based interpretation.

  1. 01Define the outcome and pre-imaging inputs
  2. 02Prepare and validate the patient-level data
  3. 03Compare logistic regression, random forest and XGBoost
  4. 04Tune models with Optuna
  5. 05Evaluate performance and uncertainty
  6. 06Explore explanations and subgroup behaviour

05 / CLINICAL MACHINE LEARNING

Interpretation & robustness

SHAP and subgroup analysis are part of the reported project. They provide a way to investigate model behaviour beyond a single aggregate score.

  • Interpretation: explore how clinical inputs contribute to predictions without treating model explanations as causal evidence.
  • Subgroups: examine whether performance estimates vary across patient groups, alongside their sample sizes and uncertainty.
  • Clinical comparison: document the reported comparison with RACE using the same evaluation population and transparent threshold choices.

No feature ranking or subgroup result is asserted here without the supporting output.

06 / CLINICAL MACHINE LEARNING

From model to prototype

The project includes an exploratory Streamlit LVO Risk Assistant for communicating predictions in an interactive clinical decision-support format.

This adds a product question to the modelling work: how should a research result be presented so that its meaning, uncertainty and limitations remain visible?

Research prototype. Clinical deployment and external validation are not established in the supplied material. This portfolio does not offer patient-specific risk predictions.

07 / CLINICAL MACHINE LEARNING

Limitations & next steps

  • Check the complete evaluation protocol and uncertainty estimates against the thesis.
  • Assess the limits of a modest, single-setting cohort and its relevance to other populations.
  • Document calibration, missing-data handling, class imbalance and threshold selection.
  • Evaluate on independent data before drawing conclusions about generalisability.
  • Study clinical usefulness and workflow fit separately from predictive performance.

The contribution: a biomedical question developed into an end-to-end clinical modelling project, with interpretation and practical use considered alongside performance.
