01 / CLINICAL MACHINE LEARNING

The clinical question

Can information collected during the initial clinical assessment help identify patients with large vessel occlusion before imaging is available?

My contribution focused on scientific and clinical interpretation, evaluation of Qwen2.5 using multiple prompting strategies, comparison of LLM and supervised model outputs, and development of the Streamlit clinical decision-support prototype.

The collaborative project connects a clearly defined prediction question with clinical data preparation, model comparison and interpretation. Its value lies in evaluating what the data can support while recognising where the evidence stops.

02 / CLINICAL MACHINE LEARNING

Data & study context

The completed project used a cohort of 251 acute ischemic stroke patients from Hospital Serena del Mar, with clinical variables available before neuroimaging. The completed thesis received a grade of 9.5/10.

Data protection. No patient-level records are published here.

03 / CLINICAL MACHINE LEARNING

Project modelling approach

The collaborative project workflow included data preprocessing, statistical analysis, class imbalance handling, three predictive-modelling families, hyperparameter optimisation, bootstrap confidence intervals, subgroup analysis and SHAP-based interpretation.

  1. 01Define the outcome and pre-imaging inputs
  2. 02Prepare and validate the patient-level data
  3. 03Compare logistic regression, random forest and XGBoost
  4. 04Tune project models with Optuna
  5. 05Evaluate performance and uncertainty
  6. 06Explore explanations and subgroup behaviour

These methods describe the project as a whole and are not presented as techniques that I implemented independently.

AUC summarises discrimination. Sensitivity and specificity describe a particular operating point. These figures alone do not establish calibration, clinical utility or performance in another population.

05 / CLINICAL MACHINE LEARNING

Interpretation & robustness

Within the collaborative project, SHAP and subgroup analysis were used to investigate model behaviour beyond a single aggregate score.

  • Interpretation: explore how clinical inputs contribute to predictions without treating model explanations as causal evidence.
  • Subgroups: examine whether performance estimates vary across patient groups, alongside their sample sizes and uncertainty.
  • Clinical comparison: compare project outputs with RACE using the same evaluation population and transparent threshold choices.

No feature ranking or subgroup result is asserted here without its supporting output.

06 / CLINICAL MACHINE LEARNING

LLM evaluation & prototype

I evaluated Qwen2.5 using multiple prompting strategies and compared the LLM outputs with those of the supervised models used in the collaborative project.

I also developed an exploratory Streamlit LVO Risk Assistant for communicating predictions in an interactive clinical decision-support format.

This adds a product question to the modelling work: how should a research result be presented so that its meaning, uncertainty and limitations remain visible?

Research prototype. This is not a deployed clinical tool and does not offer patient-specific medical advice. External validation and prospective evaluation would be required before clinical use.

07 / CLINICAL MACHINE LEARNING

Limitations & next steps

  • Assess the limits of a modest, single-setting cohort and its relevance to other populations.
  • Evaluate calibration, missing-data handling, class imbalance and threshold selection when translating the research.
  • Validate performance on independent data before drawing conclusions about generalisability.
  • Study clinical usefulness and workflow fit separately from predictive performance.
  • Evaluate how reliably the LLM component generalises across prompts, cases and settings.
